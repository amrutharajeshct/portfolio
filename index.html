Unoptimized Query: Cartesian Multi-Join & Subquery in WHERE 
-- ❌ UNOPTIMIZED QUERY (Causes full table scan on 500K+ ERP records)
SELECT o.OrderID, c.CustomerName, p.ProductName, o.OrderDate, o.TotalAmount
FROM Orders o
JOIN Customers c ON o.CustomerID = c.CustomerID
JOIN Products p ON o.ProductID = p.ProductID
WHERE YEAR(o.OrderDate) = 2026 -- Non-Sargable function forces full scan
  AND o.TotalAmount > (
      SELECT AVG(TotalAmount) FROM Orders WHERE Status = 'Completed' -- Correlated subquery per row
  )
ORDER BY o.OrderDate DESC;
Bottleneck Diagnosis: Using YEAR(o.OrderDate) invalidates B-Tree index seeks on OrderDate. The scalar subquery recalculates per outer row, creating massive disk I/O and locking issues across concurrent reporting runs.
